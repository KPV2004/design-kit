v1.2.1 — component kits for wireframes & mock v1.2.1 — ชุด component สำหรับ wireframe และ mock

Describe an app.
Get a complete, reviewable design project.

A skill for Claude and other AI agents that turns one prompt into wireframes of every screen, a clickable mock with a realtime theme picker, a stand-alone UX spec, dev diagrams and design tokens — kept in sync whenever you ask for a change.

บอกไอเดียแอป
ได้โปรเจกต์ดีไซน์ที่รีวิวได้ครบ พร้อมส่งทีม dev

Skill สำหรับ Claude และ AI agent อื่น ๆ เปลี่ยนพรอมป์เดียวเป็น wireframe ทุกหน้าจอ, mock ที่คลิกได้พร้อมเลือก theme แบบเรียลไทม์, UX spec ที่ dev ใช้ได้เลย, diagram และ design tokens — แก้ตรงไหน ทุกไฟล์อัปเดตตาม

Procura — แอปอนุมัติใบสั่งซื้อที่สร้างด้วย skill นี้ และใช้เป็นชุดทดสอบของโปรเจกต์ มี 5 หน้าจอ รองรับทุกขนาดจอ ทั้ง theme สว่างและมืด ผ่าน verify.py ทุกครั้งที่มีการแก้

ทุกหน้าแบบ low-fi, Desktop / Tablet / Mobile, ซูม, ปักหมุดความเห็น, หน้า Diagrams และ Components

hi-fi ที่คลิกได้: สลับอุปกรณ์, state (ว่าง / โหลด / ผิดพลาด) และ theme ได้จาก toolbar

design.md · ux-spec.md →

The source of truth: tokens with contrast ratios, state matrix, exact error text, API contract.

แหล่งข้อมูลหลัก: tokens พร้อมค่า contrast, ตาราง state, ข้อความ error, API contract

What you get

One folder, cross-checked by a script before handover.

Wireframes — every screen

Login, 403/404, empty states, session expired — not just the happy path. Desktop / Tablet / Mobile frames, zoom & pan, pinned comments.

Component kits

~35 grayscale wf-* blocks and themeable mk-* components with every state built in — galleries with copyable markup in both files.

Clickable mock + themes

Device preview, state switcher, realtime theme picker (Default / Dark / presets). Text stays ≥ 4.5:1 in every theme.

A spec devs implement from

State matrix, exact error text, interactions, copy deck (EN/TH), API contract — nobody reopens app code.

Dev diagrams + tokens

User flow, ER, state and sequence diagrams in Mermaid; tokens.css / Tailwind / JSON with dark values and a Flutter mapping.

Changes propagate, then verify

"Add a phone field" edits every affected file. verify.py checks pairing, tokens, icons, diagrams and stale engines.

สิ่งที่ได้

โฟลเดอร์เดียว มีสคริปต์ตรวจความสอดคล้องก่อนส่งมอบทุกครั้ง

Wireframe ครบทุกหน้าจอ

Login, 403/404, หน้าว่าง, session หมดอายุ — ไม่ใช่แค่ happy path มี frame Desktop / Tablet / Mobile, ซูม-เลื่อน, ปักหมุดความเห็น

ชุด component

wf-* แบบขาวดำ ~35 ชิ้น และ mk-* ที่เปลี่ยนตาม theme พร้อมทุก state — มีแกลเลอรีให้ copy โค้ดทั้งสองไฟล์

Mock คลิกได้ + theme

ดูตัวอย่างตามอุปกรณ์, สลับ state, เลือก theme แบบเรียลไทม์ (Default / Dark / preset) ตัวอักษรผ่าน 4.5:1 ทุก theme

Spec ที่ dev ใช้ได้เลย

ตาราง state, ข้อความ error ตรงตัว, interactions, copy deck (EN/TH), API contract — ไม่ต้องเปิดโค้ดเดิม

Diagram + tokens

User flow, ER, state, sequence ใน Mermaid; tokens.css / Tailwind / JSON พร้อมค่า dark และ mapping สำหรับ Flutter

แก้จุดเดียว อัปเดตทุกที่

"เพิ่มช่องเบอร์โทร" แก้ทุกไฟล์ที่เกี่ยวข้อง แล้ว verify.py ตรวจการจับคู่หน้าจอ, tokens, icon, diagram และ engine ที่ล้าสมัย

Installติดตั้ง

Inside a Claude Code session:

ใน session ของ Claude Code:

/plugin marketplace add KPV2004/design-kit
/plugin install design-kit@design-kit

Invoke it by asking for a design, or explicitly with /design-kit:design-kit.

ขอให้ออกแบบได้เลย หรือเรียกตรง ๆ ด้วย /design-kit:design-kit

  1. Download design-kit.zip from the latest release.
  2. Enable Code execution and file creation in Settings → Capabilities.
  3. Customize → Skills → + → Upload a skill, choose the zip.
  1. ดาวน์โหลด design-kit.zip จาก release ล่าสุด
  2. เปิด Code execution and file creation ใน Settings → Capabilities
  3. ไปที่ Customize → Skills → + → Upload a skill แล้วเลือก zip

Standard Agent Skills format — the skills CLI copies it to every agent you have:

เป็น Agent Skills รูปแบบมาตรฐาน — skills CLI จะ copy ไปให้ทุก agent ที่มีในเครื่อง:

npx skills add KPV2004/design-kit

Pick agents with -a codex -a cursor. Written and tested with Claude; other models vary.

เลือก agent ด้วย -a codex -a cursor เขียนและทดสอบกับ Claude โมเดลอื่นผลอาจต่างกัน

git clone https://github.com/KPV2004/design-kit.git
cp -r design-kit/skills/design-kit ~/.claude/skills/design-kit

Use .claude/skills/ inside a repo to install for that project only; ~/.agents/skills/ for Codex, Cursor and others. Restart the agent after copying.

ใช้ .claude/skills/ ใน repo ถ้าจะติดตั้งเฉพาะโปรเจกต์นั้น และ ~/.agents/skills/ สำหรับ Codex, Cursor และอื่น ๆ แล้วรีสตาร์ท agent

Requirements: Python 3.9+. Optional: pip install playwright && playwright install chromium turns on browser checks (JS errors, icon names, Mermaid syntax).

สิ่งที่ต้องมี: Python 3.9+ ไม่บังคับ: pip install playwright && playwright install chromium เพื่อเปิดการตรวจในเบราว์เซอร์ (JS error, ชื่อ icon, Mermaid)

Usage

The skill triggers on its own, in English or Thai. To change something later, just say it — every affected file is edited and the version bumped.

วิธีใช้

skill ทำงานเองเมื่อขอให้ออกแบบ จะพิมพ์ไทยหรืออังกฤษก็ได้ อยากแก้อะไรภายหลังก็บอกได้เลย — ทุกไฟล์ที่เกี่ยวข้องถูกแก้และ bump version ให้

Design a purchase-order approval system for a factory:
list, detail, approve/reject, dashboard.
Users are office staff who use Dynamics AX all day.
ออกแบบแอปจดรายรับรายจ่ายบนมือถือ
มีหน้าบันทึก สรุปรายเดือน และตั้งงบประมาณ
สีหลักเป็นสีส้ม แล้วทำ mock พร้อมเลือก theme ให้ด้วย
"เปลี่ยนสีหลักเป็นเขียว" "add a Tablet layout" "remove the dashboard" "Wireframe feedback — …"

Updatingการอัปเดต

The skill (marketplace)ตัว skill (marketplace)

claude plugin marketplace update design-kit
claude plugin update design-kit@design-kit

claude.ai: download the new zip and replace the upload. Manual copy: git pull, copy again, restart the agent.

claude.ai: ดาวน์โหลด zip ใหม่แล้วอัปโหลดทับ แบบ copy เอง: git pull แล้ว copy ใหม่ และรีสตาร์ท agent

Existing design projectsโปรเจกต์ดีไซน์ที่สร้างไว้แล้ว

Each project keeps its own _engine/ and _tools/. verify.py warns when they are older than the skill; refresh both from the project folder:

แต่ละโปรเจกต์มี _engine/ และ _tools/ ของตัวเอง verify.py จะเตือนเมื่อเก่ากว่า skill — อัปเดตทั้งคู่จากในโฟลเดอร์โปรเจกต์:

python _tools/update_engine.py ~/.claude/skills/design-kit
python _tools/verify.py .

Projects made before 1.2.1 have no update_engine.py yet — copy it once from skills/design-kit/scripts/.

โปรเจกต์ที่สร้างก่อน 1.2.1 ยังไม่มี update_engine.py — copy จาก skills/design-kit/scripts/ ครั้งแรกครั้งเดียว

Contributing

Before a pull requestก่อนเปิด pull request

./tools/check.sh          # what CI runs
./tools/check.sh --fast   # without browser tests

Unit tests, verify.py on the Procura example, browser tests (state switcher, contrast in every theme, JS errors) and the zip build.

unit test, verify.py กับตัวอย่าง Procura, ทดสอบในเบราว์เซอร์ (ตัวสลับ state, contrast ทุก theme, JS error) และ build zip

Releasingออก release

./tools/release.sh prepare 1.3.0   # opens the release PR
./tools/release.sh tag 1.3.0       # after merging it

Writes the version everywhere it lives and only tags when main already says it — the Release workflow then builds the zip.

เขียนเลข version ลงทุกที่ที่ใช้ และจะสร้าง tag เมื่อ main เป็นเลขนั้นแล้วเท่านั้น จากนั้น Release workflow จะ build zip ให้
